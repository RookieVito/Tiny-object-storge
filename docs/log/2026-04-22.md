### Bug 修复：分布式模式 Quorum 失败 + Phase 3 POST → 405

#### 分布式模式 CreateBucket 返回 503

**现象**：3 节点分布式集群启动后，创建 Bucket 返回 503 `Failed to achieve write quorum`。

**根因 1 — seed_nodes 格式错误**：示例配置文件中 `seed_nodes` 包含 `http://` 前缀（`"http://localhost:9001"`），`transport.nodeURL()` 再拼接 `http://` 前缀，导致 RPC URL 变为 `http://http://localhost:9001/_cluster/replicate`，所有跨节点 RPC 请求失败。

**修复**：`example/distributed/node{1,2,3}-config.json` 中 `seed_nodes` 去掉 `http://` 前缀（`"localhost:9001"`），并在 README 中注明格式要求。

**根因 2 — replicas() 竞态条件**：`replicas()` 直接使用哈希环选节点，但节点加入哈希环是异步的（`mergePayload` 通过 `go fireJoin()` goroutine 执行 `ring.AddNode`）。在节点加入成员表（alive）和加入哈希环之间存在短暂窗口，`replicas()` 可能返回不完整的节点列表，导致 quorum 不足。

**修复**：`src/storage/distributed.go` 的 `replicas()` 方法改为先通过 `membership.AliveNodes()` 获取存活节点集合，再从哈希环候选节点中过滤出 alive 节点，确保只选择可到达的节点。同时在 `CreateBucket` 中添加 debug/warn 级别日志，记录副本选择和失败详情。

#### Phase 3 Metrics POST → 405

**现象**：Phase 3 测试 `Metrics: POST → 405` 预期返回 405，但实际返回 307 重定向。

**根因**：`topMux.Handle("GET /_metrics", m)` 使用了方法限定的路由注册，ServeMux 对 POST 请求到 `GET /_metrics` 返回 307 重定向而非 405。

**修复**：改为 `topMux.Handle("/_metrics", m)`，让所有 HTTP 方法到达 handler，handler 内部判断方法并返回 405。
